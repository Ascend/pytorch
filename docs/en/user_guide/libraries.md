# Supporting Software Libraries

To extend the capabilities of TorchNPU, Ascend provides the following self-developed plugins.

|Name|Description|Version Requirements|Adaptation Description|
|--|--|--|--|
|TorchAir|TorchAir is an extension library that provides graph mode capabilities for TorchNPU, enabling users to perform graph-mode training and inference on Ascend devices using PyTorch and TorchNPU. TorchAir provides a graph-mode compilation backend for Ascend devices. It interfaces with the PyTorch Dynamo feature to convert PyTorch FX computation graphs into Ascend GE computation graphs and provides the capability to initiate GE computation graph compilation and execution on Ascend devices.|PyTorch version 2.6.0 or later.<br>TorchNPU version master.|For detailed usage, refer to [TorchAir](https://gitcode.com/Ascend/torchair/blob/master/docs/en/_menu_torchair.md).|
|OpPlugin|The OpPlugin plugin provides the capability to map PyTorch operators to Ascend AI processors, offering developers who use the PyTorch framework convenient NPU operator library invocation capabilities.|OpPlugin version master.|Refer to [LINK](https://gitcode.com/Ascend/op-plugin/tree/master) to install this library. For the custom operator adaptation development process and usage examples based on the OpPlugin plugin, see the "[OpPlugin-Based Operator Adaptation Development](../developer_notes/custom_operator_adaptation/opplugin_operator_adaptation/adaptation_overview_opplugin.md)" section in *Framework Features*.<br>PyTorch officially provides C++ extensions for users to write and invoke custom operators. Users can choose to use C++ extensions for custom operator development and adaptation. For details, see the "[C++ Extensions-Based Operator Adaptation Development](../developer_notes/custom_operator_adaptation/c_extensions_operator_adaptation.md)" section in *Framework Features*.|
|HyperParallel|HyperParallel is a high-performance distributed parallel acceleration library designed for Ascend super nodes, providing full-scenario distributed parallel acceleration capabilities for Ascend NPUs, simplifying super node programming and unleashing compute potential. Its core features include:<br>1. **Support for native Hugging Face model distributed training**: Supports loading Hugging Face model configurations and pretrained weights, and supports secondary development based on Transformers models. Through Ascend high-performance module injection and declarative parallel configuration, HuggingFace models can be trained on Ascend in an extremely simple and efficient way.<br>2. **Declarative programming interface**: Following the design philosophy of decoupling the model from system optimization, it implicitly injects system optimizations such as parallelism, recomputation, and Offload through declarative programming interfaces (`shard_module`, `parallelize_module`). Users can obtain distributed parallel acceleration without modifying model code, greatly lowering the development threshold for distributed training of large models.<br>3. **FSDP/HSDP data parallelism**: Supports full sharding of parameters, gradients, and optimizer states (`fully_shard`), provides the HSDP hybrid sharded data parallel module (`HSDPModule`) and a fully overlapped communication-and-computation concurrency mode, greatly reducing per-device memory usage and improving training throughput.<br>4. **Full-paradigm parallelism**: Covers parallel paradigms such as TP (declarative Colwise/Rowwise/SequenceParallel), EP (ExpertParallel/ExpertTensorParallel), CP (ContextParallel/AsyncContextParallel/DSA series), and PP (1F1B/VPP/GPipe and communication-computation overlap), supporting multi-dimensional hybrid parallelism of PP+FSDP+TP+CP+EP.|HyperParallel version 1.1.0.<br>PyTorch version 2.6.0 or later.|For detailed usage, refer to [HyperParallel Usage Guide](https://gitcode.com/mindspore/hyper-parallel/blob/master/README.md) and [HyperParallel Documentation Center](https://gitcode.com/mindspore/hyper-parallel/blob/master/docs/index.md).|
|AKG|AKG (Auto Kernel Generator) is an MLIR-based automatic operator generation component that provides operator-level compilation and execution capabilities for the Inductor backend. AKG converts Torch MLIR delivered from the PyTorch side and compiles it into high-performance kernels adapted to Ascend AI processors. Through compilation caching, automatic optimization, and runtime loading capabilities, it reduces manual operator adaptation costs, greatly shortening compilation time and improving model execution performance.|PyTorch version 2.7.1 or later.<br>TorchNPU version master.|For detailed usage, refer to the [AKG Usage Guide](https://gitcode.com/mindspore/akg/blob/br_schedule/akg-mlir/README.md)|
|Triton Ascend|Triton Ascend is an optimized version of Triton adapted to Ascend AI processors. It provides efficient kernel function auto-tuning, operator compilation, and deployment capabilities, and supports <term>Atlas A2 products</term> and <term>Atlas A3 products</term>. While compatible with core Triton syntax, it has been deeply optimized for Ascend NPU features, including automatic parsing of kernel function parameters, optimized memory access logic, and improved secure deployment mechanisms.|Triton Ascend version latest.<br>PyTorch version 2.7.1 and 2.9.0.<br>TorchNPU version master.|For detailed usage, refer to [Triton Ascend](https://triton-ascend.readthedocs.io/en/latest/).|
