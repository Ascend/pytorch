# Inductor

## Introduction

Inductor is the default backend compiler of `torch.compile()`. Through the collaboration of "Dynamo frontend graph capture + Inductor backend optimization + high-performance operator generation", it automatically performs operator fusion and code generation without changing the model logic, significantly improving training or inference throughput.

The Inductor backend supports four operator compilers, which can be selected based on the scenario:

| Compiler | Mode | How to Enable | Description |
| - | - | - | - |
| Triton | Default mode |`torch.compile(backend="inductor")`| Generates fused operators based on Triton. It is the default choice of the Inductor backend and is suitable for most scenarios. For detailed information, see the [Triton-Ascend official repository](https://gitcode.com/Ascend/triton-ascend).|
| DVM | DVM mode |`torch.compile(backend="inductor", options={"npu_backend": "dvm"})` | Generates fused operators based on DVM. For detailed information, see the [DVM official repository](https://gitcode.com/mindspore/dvm/tree/master).|
| Ascend C | Ascend C mode |`torch.compile(backend="inductor", options={"npu_backend": "ascendc"})` | Generates fused operators based on Ascend C. For detailed information, see the [Autofuse official repository](https://gitcode.com/cann/graph-autofusion/blob/9.2.0/autofuse/README.md).|

> [!NOTICE]
>
> - Before using the Inductor backend, install the Triton Ascend version that matches the PyTorch version first. This version supports only PyTorch 2.7.1, 2.10.0, and 2.13.0. The installation instructions for Triton Ascend are as follows:
>   - For source code compilation or online installation (Pip), the system installs the matching version of Triton Ascend by default.
>   - For offline installation (Whl), refer to the [Quick Installation](https://www.hiascend.com/developer/software/ai-frameworks/pytorch/download?versionId=180&ids=89dda9ba9de741349efa03687a487678%2C204%2C200%2C1%2C6%2C177%2C) document and run the commands in it for installation.
> - For more information about Triton Ascend, refer to [Triton Ascend](https://triton-ascend.readthedocs.io/en/latest/).<br>
> - Before importing torch, you can also select the compiler mode through the TORCHINDUCTOR_NPU_BACKEND environment variable. For details, see [TORCHINDUCTOR_NPU_BACKEND](../../../api/environment_variable/inductor/TORCHINDUCTOR_NPU_BACKEND.md).

## Compiler

### Triton (Default Mode)

Triton is the default operator compiler of Inductor. While retaining the core logic of torch.compile dynamic graph capture + static graph optimization + efficient code generation, it leverages Triton's automatic Tiling and fused operator generation capabilities to significantly reduce the developer workload of manually designing Tiling and managing memory, improving performance by reducing the number of memory accesses.

The Triton compiler includes the following core components:

| Component | Positioning | Function |
| - | - | - |
| Inductor-Triton | Core compiler (fused operator generator) | Automatically generates high-performance fused operators based on Triton-Ascend. Through strategies such as operator fusion, data type optimization, and computation graph simplification, it balances compilation flexibility and optimization depth. |
| Triton CodeGen | Code generator (hardware-aware code generator) | Receives the optimized computation graph and generates dedicated high-performance low-level code for the target hardware (NPU), automatically completing Tiling and shared memory management. |

#### Calling Example

```python
import os
os.environ['TORCHINDUCTOR_NPU_BACKEND'] = 'default'

import torch
import torch_npu
from torch._inductor.utils import run_and_get_code

# Define the model
def op_calc(x, y):
    return x * y

x = torch.randn((3,), requires_grad=False, dtype=torch.float32, device="npu")
y = torch.randn((3,), requires_grad=False, dtype=torch.float32, device="npu")
std_out = op_calc(x, y)

compile_func = torch.compile(op_calc, backend="inductor")
compile_out, codes = run_and_get_code(compile_func, x, y)
print(codes[0])
```

#### Output Triton Fused Operators

After Triton compilation, fused operator code is generated internally, which can be viewed through `codes[0]`:

```python
def call(args):
    arg0_1, arg1_1 = args
    args.clear()
    with torch.npu.utils.device(0):
        torch.npu.set_device(0)
        buf0 = empty_strided((3, ), (1, ), device='npu', dtype=torch.float32)
        # Topologically Sorted Source Nodes: [mul], Original ATen: [aten.mul]
        stream0 = get_raw_stream(0)
        triton_poi_fused_mul_0.run(arg0_1, arg1_1, buf0, 3, stream=stream0)
        del arg0_1
        del arg1_1
    return (buf0, )
```

Here, `triton_poi_fused_mul_0` is the core execution interface generated by Triton compilation, used to execute fused operator computation on the specified NPU device and computation stream.

### DVM

DVM is an optional operator compiler for Inductor, generating fused operators based on DVM.

DVM currently supports two fusion modes: mlir_fusion and graph_fusion, corresponding to two strategies: reusing Inductor-MLIR fusion results and custom graph fusion paths.

| Mode | Depends on Inductor MLIR | Pattern Control | Applicable Scenarios |
| - | - | - | - |
| mlir_fusion | Yes | Low | Reuses Inductor fusion results |
| graph_fusion | No | High | Custom/complex/experimental fusion | 

#### Calling Example

```python
import os
os.environ['TORCHINDUCTOR_NPU_BACKEND'] = 'dvm'

import torch
import torch_npu
import torch_npu._inductor

# mlir_fusion mode
torch._inductor.config.npu_backend = "dvm"

# Define the model
def op_calc(x, y):
    return x * y

x = torch.randn((3,), requires_grad=False, dtype=torch.float32, device="npu")
y = torch.randn((3,), requires_grad=False, dtype=torch.float32, device="npu")

# Compile and execute
compile_func = torch.compile(op_calc, backend="inductor", options={"npu_backend": "dvm"})
out = compile_func(x, y)
```

#### Output DVM Fused Operators

After DVM compilation, the corresponding fused operator code is generated. Examples of the output for the two modes are as follows:

**mlir_fusion mode output:**

### Ascend C

Ascend C is an optional operator compiler for Inductor, generating fused operators based on Ascend C.

#### Calling Example

```python
import os
os.environ['TORCHINDUCTOR_NPU_BACKEND'] = 'ascendc'

import torch
import torch_npu
from torch._inductor.utils import run_and_get_code
import torch_npu._inductor

# Define the model
def op_calc(x, y):
    return x * y

x = torch.randn((3,), requires_grad=False, dtype=torch.float32, device="npu")
y = torch.randn((3,), requires_grad=False, dtype=torch.float32, device="npu")
std_out = op_calc(x, y)

compile_func = torch.compile(op_calc, options={"npu_backend": "ascendc"})
compile_out, codes = run_and_get_code(compile_func, x, y)
print(codes[0])
```

#### Output Ascend C Fused Operators

After Ascend C compilation, fused operator code is generated internally, which can be viewed through `codes[0]`:

```python
def call(self, args):
    arg0_1, arg1_1 = args
    args.clear()
    # Topologically Sorted Source Nodes: [mul], Original ATen: [aten.mul]
    # Source node to ATen node mapping:
    #   mul => mul
    # Graph fragment:
    #   %arg0_1 : Tensor "f32[3][1]npu:0" = PlaceHolder[target=arg0_1]
    #   %arg1_1 : Tensor "f32[3][1]npu:0" = PlaceHolder[target=arg1_1]
    #   %mul : Tensor "f32[3][1]npu:0"[num_users=1] = call_function[target=torch.ops.aten.mul.Tensor](args = (%arg0_1, %arg1_1), kwargs = {})
    #   return %mul
    buf0 = empty_strided((3, ), (1, ), device='npu', dtype=torch.float32)
    from torch_npu._inductor.ascendc.common.fused_layout_check import check_fused_layout
    _enable_layout_check = os.getenv("TORCH_COMPILE_DEBUG", "0") == "1" or os.getenv("TORCHINDUCTOR_NPU_EXT_LAYOUT_CHECK", "0") == "1"
    if _enable_layout_check:
        kernel_name='autofused_mul_da488cd9dfe43526f023de214ab2ff6a'
        check_fused_layout(kernel_name, 'arg0_1', arg0_1, (3,), (1,), torch.float32, 'npu')
        check_fused_layout(kernel_name, 'arg1_1', arg1_1, (3,), (1,), torch.float32, 'npu')
    autofused_mul_da488cd9dfe43526f023de214ab2ff6a(arg0_1, arg1_1, buf0)
    del arg0_1
    del arg1_1
    return (buf0, )
```

Here, `autofused_mul_da488cd9dfe43526f023de214ab2ff6a` is the core execution interface generated by Ascend C compilation, used to execute fused operator computation on the specified NPU device and computation stream.

## Compilation Mode

`mode="reduce-overhead"` is an optimization strategy for reducing overhead, corresponding in essence to the logic of **NPUGraph Tree**:

- **Dynamic shape routing**: Manages multiple associated NPUGraphs so that the optimization benefits of NPUGraphs can cover dynamic shape scenarios rather than being limited to fixed shapes.
- **Subgraph memory optimization**: Optimizes the memory usage of multiple subgraphs in segment graph scenarios.
- **Working principle**: With multiple inputs of different shapes, the Tree caches multiple captured graph versions and automatically routes to the best-matching subgraph for replay based on the input shape.

For more details, see [CUDAGraph Trees](https://docs.pytorch.org/docs/stable/user_guide/torch_compiler/torch.compiler_cudagraph_trees.html).

Example of enabling NPUGraph Tree logic:

```python
compiled_model = torch.compile(
    model,
    backend="inductor",
    mode="reduce-overhead"  # Enable NPUGraph Tree logic
)
```

## Compilation Options

Compilation options supported by Inductor (the `options` parameter):

| Option | Description |
| - | - |
| `triton.cudagraphs` | Triton-related configuration |
| `trace.enabled` | Tracing switch |
| `enable_shape_handling` | Shape handling configuration |
| `npu_backend` | Specifies the operator compiler (`"dvm"` or `"ascendc"`; Triton by default) |

## Constraints

1. Optimizers are usually not included in the graph. The optimizer's `step()` contains Python-side dynamic logic (such as learning rate scheduling, gradient accumulation, and adaptive update rules), which is difficult to capture in a static graph.
2. `torch.compile(backend="inductor")` supports dynamic shapes, but triggers recompilation (adding overhead). It is recommended to fix the shape as much as possible.
