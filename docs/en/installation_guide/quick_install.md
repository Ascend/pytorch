>
>     ```bash
>     pip3 download --platform manylinux_2_28_aarch64 --python-version 3.14 --only-binary=:all: --extra-index-url https://ascend.devcloud.huaweicloud.com/pypi/simple/ --dest ./ torch_npu==2.14.0
>     ```
>
>   `--platform` is not the kernel version and does not automatically include compatibility tags for lower glibc versions. >
>     ```bash
>     pip3 download --python-version 3.9 --only-binary=:all: \
>       --platform manylinux_2_28_aarch64 \
>       --platform manylinux_2_27_aarch64 \
>       --platform manylinux2014_aarch64 \
>       --dest ./ numpy==2.0.2
>     ```
>
> - If an error such as "google or protobuf not found, or protobuf version too high" occurs, run the following command in the package directory:
>
>     ```bash
>     pip3 install --no-index --find-links=./ protobuf==3.20
>     ```

### Environment Preparation

> [!NOTICE]
>
> It is recommended to use a non-root user to install and run programs, and to control the permissions of the installation directory and files: set folder permissions to 750 and file permissions to 640. You can control the permissions of installed files by setting umask, for example, to 0027. For more security-related content, see the descriptions about "File Permission Control" of each component in the [Security Statement](../reference/security_statement.md).

- Install the matching NPU driver and firmware, CANN software (Toolkit, ops, and NNAL), and configure the CANN environment variables. For details, see [CANN Software Installation](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/920/softwareinst/instg/instg_0000.html?OS=openEuler&InstallType=netyum).

    CANN software provides a process-level environment variable setting script. Before executing business code on the NPU in training or inference scenarios, call this script; otherwise, the business code cannot be executed.

    ```bash
    source /usr/local/Ascend/cann/set_env.sh
    source /usr/local/Ascend/nnal/atb/set_env.sh
    ```

    The preceding commands use the default paths after installation by the root user as an example. Replace them with the actual path of set\_env.sh.

- Python 3.11 provides better scheduling (dispatch) performance than Python 3.10. Python 3.11 or later is recommended.

## Post-Installation Verification

Run the following commands to check whether the PyTorch framework and TorchNPU plugin have been successfully installed.

```Python
python3 -c "import torch;import torch_npu; a = torch.randn(3, 4).npu(); print(a + a);"
```

If the output contains similar information, the installation is successful.

```text
tensor([[-0.6066,  6.3385,  0.0379,  3.3356],
        [ 2.9243,  3.3134, -1.5465,  0.1916],
        [-2.1807,  0.2008, -1.1431,  2.1523]], device='npu:0')
```

To view the installed Python, PyTorch, and TorchNPU versions in the current environment, see [Checking Versions](./references/check_installed_versions.md).

## Building from Source

For most users, it is recommended to install the PyTorch framework and TorchNPU plugin directly using the precompiled .whl packages to simplify the installation process and obtain a more stable experience. To perform feature tests, secondary development, or custom builds, see [Building from Source](./references/building_from_source.md) to compile from the source code and obtain the required .whl packages.

## Installing Extension Modules

For most users, installing the PyTorch framework and TorchNPU plugin meets the basic training and inference requirements. However, in specific development scenarios, you may also need to install corresponding extension modules. For example, to develop using the C++ interface, see [Building libtorch_npu](./references//building_libtorch_npu.md); to work on computer vision tasks, see [Installing torchvision](https://pytorch.org/get-started/locally/).
